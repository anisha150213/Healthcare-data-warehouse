# Healthcare-data-warehouse

This repository contains the HI 741 final project: a Tkinter-based user interface for a small clinical data warehouse. The application allows authorized hospital users to log in, access functions based on their role, view or update patient information when permitted, generate clinical summaries, and produce usage statistics.

## Features

- Tkinter graphical user interface with a login screen and role-based action menu.
- Credential validation using `Data/credentials.csv`.
- Strict role-based access so administrative and management users are not prompted for patient-level PHI.
- Patient record operations for authorized clinical users.
- Clinical note lookup by patient and date.
- Encounter counting by date, patient, and department.
- Eligible patient identification using clinical criteria.
- Key statistics report generation with an optional chart.
- Provider workload ranking.
- Department revenue calculation from procedure costs.
- Persistent CSV updates after adding or removing patient records.
- Usage logging for successful logins, failed login attempts, user actions, and exits.

## Requirements

- Python 3.10 or newer is recommended.
- Tkinter is required and is included with most standard Python installations.
- Matplotlib is optional but recommended for generating the chart in `output/patient_gender_counts.png`.

Install the Python package requirement with:

```bash
pip install -r requirements.txt
```

## How to Run

From the project root directory, generate the sample dataset:

```bash
python data_generator.py
```

Then start the application:

```bash
python main.py
```

The application opens a login window. After a valid username and password are entered, the menu displays only the actions allowed for that user's role.

## User Roles and Permissions

| Role | Access |
| --- | --- |
| `clinician` | Can access patient information and perform all clinical actions, including add, remove, retrieve, count visits, view notes, identify eligible patients, generate statistics, monitor workload, and monitor revenue. |
| `nurse` | Same clinical access as clinicians. |
| `admin` | Cannot access PHI. Can count visits, count encounters per patient, count encounters by department, monitor provider workload, and generate non-PHI statistics. |
| `management` | Cannot access PHI. Can generate key statistics and monitor department revenue. |

## Implemented Actions

The UI supports the required project actions:

- `Add_patient`: Adds a new patient or adds a new visit for an existing patient. Changes are written back to the CSV files.
- `Remove_patient`: Removes the patient and related encounter, procedure, and note records.
- `Retrieve_patient`: Displays patient demographics and most recent visit information.
- `Count_visits`: Counts total visits on a given date and summarizes visits by patient and department.
- `View_Note`: Displays clinical notes for a patient on a selected date.
- `Generate_key_statistics`: Creates and displays summary statistics, writes `output/key_statistics.txt`, and creates a chart if Matplotlib is installed.
- `Monitor_revenue`: Computes total procedure costs by department.
- `Monitor_workload`: Ranks providers by number of encounters handled.

The UI also supports the related PA2-style summary actions mentioned in the project description:

- Count encounters per patient.
- Count encounters by department.
- Identify eligible patients.

## Input Files

All input files are stored under the relative `Data/` folder. No absolute paths are hard coded.

Required files:

- `Data/credentials.csv`
- `Data/patients.csv`
- `Data/providers.csv`
- `Data/departments.csv`
- `Data/encounters.csv`
- `Data/procedures.csv`
- `Data/notes.csv`

If these files are missing, run:

```bash
python data_generator.py
```

## Output Files

The application writes reports and logs to the `output/` folder:

- `output/usage_statistics.csv`: Records successful logins, failed login attempts, actions performed, timestamps, usernames, and roles.
- `output/key_statistics.txt`: Summary statistics generated from the clinical data.
- `output/patient_gender_counts.png`: Optional chart generated by Matplotlib.
- `output/encounters_per_patient.csv`: Encounter counts grouped by patient.
- `output/encounters_by_department.csv`: Encounter counts grouped by department.
- `output/provider_workload.csv`: Provider encounter counts sorted by workload.
- `output/department_revenue.csv`: Total procedure revenue by department.

Patient-related updates are also saved back to:

- `Data/patients.csv`
- `Data/encounters.csv`
- `Data/procedures.csv`
- `Data/notes.csv`
